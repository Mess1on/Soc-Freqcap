# 深度睡眠

（返回 [README](../README.md)）

## 深度睡眠（V2.1）

熄屏、没在充电、满 20 秒后开始深睡；满 7 分 30 秒让系统进入 Doze 深度空闲
（`force-idle deep`），并把 push / 短信 / 媒体临时加进 Doze 白名单。
亮屏或插上电立刻撤白名单、退出强制空闲。它关的是"系统空闲时还在后台折腾"，
和上面那条「熄屏交还系统」不冲突：一个管 CPU 上限，一个管系统睡眠。

**本版起只做 Doze，不再冻结任何进程。** 墓碑冻结（cgroup freezer）已整体移除：
它会把进程硬按在原地，和系统自己的冻结器抢同一批进程，用户侧表现为收不到消息。
升级上来的机器如果还留着旧版本写的冻结账本/冻结组，启动和退出时会按账本解开。

**默认是关的。** 打开入口在「睡眠」页顶部的总开关；关闭时脚本不碰任何系统 Doze 设置。
打开后由 `service.sh` 拉起独立守护，暂停模块会先让它退出并还原。

页面上的三块：

- **总开关 / 状态**：未启用、监测中（熄屏 20 秒后开始压制后台）、深度睡眠中、守护没在跑。
- **永久豁免**：名单里的应用不会被冻结，深睡时也能被正常唤醒（等同系统电量设置里的「无限制」）。
  深睡期间正在播放音乐的应用会自动临时解冻，退出深睡后重新冻上；新加进豁免名单的应用
  在当次深睡里也会立即生效。
  **系统默认短信应用即使不在名单里，进入时也会临时加白、退出时撤销**：否则 Doze 会把
  短信广播压到出 Doze 才发，表现就是"解锁后一下收到半小时前的短信"。默认应用优先用
  `cmd role get-role-holders android.app.role.SMS` 取，取不到再退回旧 setting 和常见包名。
  **系统关键应用默认加入**：时钟、电话/通话、信息、联系人、日历（含荣耀/华为/OPPO/ColorOS/小米/vivo 的厂商包）。
  音乐/健康和 Scene 不再注入 Doze 白名单（改为 `nice=`，不冻结但也不保证 Doze 期间运行）；
  正在播放的音乐在进入深睡/巡检时临时加白，退出撤销。
  飞书 / Lark / WhatsApp / Telegram / Signal / LINE 不在内置清单里。
  装机时只给**本机已安装**的包写 `white=`（清单在 `scripts/builtin_white.txt`），
  不覆盖你的名单；删掉的行升级不会塞回来，上游移除的项会从白名单撤下
  （基准 `builtin_white.base.txt`）。
  **微信/QQ/TIM/企业微信/钉钉不再整包加入 white=**：旧配置会在升级后一次性迁移到
  `nice=`（保活，不冻结），微信另外写 `push=com.tencent.mm:push` 只放行推送进程。
  音乐/健康/Scene 也走 `nice=`，不再整包注入 Doze 白名单。
  深睡不冻这些保活应用；微信 push 进程仍能收消息，强制 Doze 后 QQ 等非白名单应用的后台网络仍会被限制。
- **闹钟守卫**：时钟类应用有 30 分钟内要响的闹钟时，**不进入深睡**；7:30 收口那一刻也会
  再查一次，在闹钟窗口里就先不收口，5 分钟后重试。每天设闹钟也不会整晚不深睡——只让路
  闹钟前半小时。**第三方闹钟应用请加进永久豁免**：冻结会连它的响铃一起停住。
- 系统应用没有全量加白：Doze 的豁免是按包生效，把 400 多个系统包全塞进去等于把深睡
  关掉。内置的是会影响你感知的那批（时钟/电话/信息/联系人/日历/健康）。
- **唤醒榜**：本次深睡榜 + 累计榜（拔电或重启后清零）。页面 2 秒刷新一次；
  榜单在深睡中每 15 分钟从 `dumpsys alarm` 结算一次，退出时再结算一次
  （计数器是累计量，读得慢不丢数），所以刚醒来的那一两分钟看到的还是上一次的数。

深睡 = **Doze 收口 + 唤醒锁还原**，不碰 CPU 频率/调度
（避免和模块本体的熄屏策略打架）。策略列表（都在 `dsleep.conf`）：

| 配置 | Doze 白名单 | 说明 |
|---|---|---|
| `white=` | ✅ | 用户显式豁免，整包不受 Doze 限制 |
| `nice=` | ❌ | 只是保留项，深睡不碰它 |
| `push=pkg[:proc]` | ✅（包） | 保证熄屏后消息还能进来 |
| 默认第三方 | ❌ | 交给系统 Doze 压 |

- **两个总闸**：`appops=0` 完全不碰唤醒锁；`doze=0` 完全不碰 system Doze
  （不加/删白名单、不 force-idle、不 unforce）。不写就按 1。
  注意 Doze 白名单是**包级**豁免：`push=` 写的是 `包:进程`，但加进白名单的是整个包。
- **不再冻结任何进程**：没有 cgroup 组、没有 SIGSTOP 兜底。唯一保留的是
  "按旧账本解冻"，用于升级后的收尾。
  `ds_white_snapshot` 同时认 AOSP 的裸包名和 ColorOS 的 `类型,包名,uid` 两种格式 ——
  只认后者会解析失败，导致分不清哪些包本来就在白名单里，进出一次就乱加乱删。

- **Doze 白名单只留必要项**：系统关键白名单 + `push` 包 + 短信 + 正在播放的媒体；
  音乐/健康/Scene/QQ 等不再整包常驻白名单。force-idle 才真的能压住大多数后台。
- **唤醒锁**：默认第三方包 `cmd appops set <pkg> WAKE_LOCK ignore`，先记旧模式，
  亮屏恢复；`white=`/`nice=`/`push=` 的包不碰。
- **恢复顺序**：解冻 → 唤醒锁（冻结中 appops 可能写不进去，解冻后重试）→ 撤销 Doze；
  崩溃后启动也按账本先还原。`unforce` 只在本次真的 force-idle 过时才发 ——
  没发过还去撤销，会把系统自己正在进行的深度空闲打断，下一轮它又从头进。
- **单实例锁**：`run/dsleep.lock.d` 用 mkdir 原子抢锁；刚创建还没写 pid 的锁按
  “另一个实例启动中”处理，绝不抢；看门狗重启也不会跑出两个守护互相解冻。

冻结是这套方案的主力，Doze 只是最后的收口：

- 熄屏满 20 秒开始分批冻结第三方后台：每轮最多 8 个，3 分钟内完成；队列空了每分钟
  补扫一次，接住这几分钟里刚退到后台的进程。只认 `pm list packages -3` 且
  `oom_score_adj >= 200` 的进程；前台、可见应用、输入法、桌面、无障碍、VPN、当前前台、
  `full` / `keep` 档位、正在放媒体的应用、本模块和管理器、Scene 都不冻。
  厂商自带应用（`com.coloros.` / `com.oplus.` / `com.hihonor.` / `com.google.` 等前缀）
  整片不冻：ColorOS 的时钟/健康/天气在 `-3` 清单里，冻了就是闹钟不响。
- 后端顺序：**v2 `cgroup.freeze`（优先）→ v1 独立 freezer 层级 → 都不行就这一次不冻**。
  不再有 SIGSTOP 兜底：它会进程硬按在原地，按到系统正在同步调用的进程就会把
  system_server 卡在 binder 上，watchdog 60 秒后整机重启。
  现代 Android 是混合布局：统一 v2 层级在 `/sys/fs/cgroup`，app 各自待在
  `/sys/fs/cgroup/apps/uid_X/pid_Y`；而 `/dev/freezer` 这类 v1 挂载是旧路径。
  v2 里冻结是核心功能，`cgroup.freeze` 在每个 cgroup 里都有，**不会**出现在
  `cgroup.controllers` 里 —— 按 controllers 找 `freezer` 永远找不到，会一路掉到 SIGSTOP。
  v2 的做法是**原地冻**：读 `/proc/<pid>/cgroup` 拿到它自己的组，只写那个组，
  不搬家（搬出 uid 组会让 LMKD / PSI 看不见这个进程的内存）。
  页面「深度睡眠」页会显示当前实际用的是哪一套（V2 / V1 / SIGSTOP）。
- 唤醒锁账本 `run/ops.saved` 和冻结账本一起还原。
  冻结账本 `run/freeze.saved` 每批落盘，v2 下每行还记着该进程自己的 cgroup 路径；
  亮屏、关开关、守护启动、卸载都按账本解冻。
  解冻用 `cgroup.procs` 把整个进程搬回根组再删自己的组——`tasks` 只搬主线程，
  别的线程会留在冻结点上。
- **不再改 `device_idle_constants`**：进入不再靠调低全局门槛，而是冻结 + 延迟收口。
  升级前旧版留下的快照仍会按原值把常量还原/删除。
- 7:30 的 Doze 是**一次性**：`cmd deviceidle force-idle deep` 优先，失败补发
  `dumpsys` 兼容命令，仍失败就不重试。系统把你弹出（来电、闹钟等）之后不再每 15 分钟
  压回去。

开关背后的实现约束：

- **熄屏巡检不拿 system_server 当轮询接口**：亮屏判定先读背光/blank 节点（一次 `cat`），
  节点说灭时最多每 60 秒让 `dumpsys power` 复核一次；媒体 5 分钟、唤醒数 15 分钟才读一次。
  以前每 2 秒跑 `dumpsys power`＋`dumpsys display`＋`media_session`＋`alarm`，守护自己
  就是熄屏后的常驻唤醒源；`display` 那份 dump 一旦卡住，整轮巡检就不返回，亮屏了也没人
  解冻（应用一直停在冻结组里）。
- **深睡激活后不再 2 秒轮询**：冻结窗口（前 3 分钟）每 2 秒分批；之后阻塞等
  `logcat -b events -s screen_toggled`，亮屏瞬间醒来解冻；最多 2 分钟醒一次做维护
  （充电/7:30/名单/媒体）。logcat 事件不可用时才退回 30 秒定时。
  这样守着自己不会把手机整晚钉在 awake，冻结才真的能省电。
- 每个 `dumpsys` 都套 `timeout`，卡住最多丢一轮，不会挂死守护。
- **游戏在前台时不进深睡**：主守护状态里 `game_pkg` 和 `fg` 是同一个包时（典型是熄屏挂机），
  只记一行日志、不冻结也不收口。Doze 会把游戏挂住，系统也会把这段功耗记进空闲/待机。
- 个别 ROM 的亮度节点在亮屏时也报 0：连续 3 次和 `dumpsys power` 对不上就停用节点，
  改成直接问系统（日志里会写一行）。
- 进入时写 `ds_snap.conf`（本次临时加的白名单）；正常退出删除它。启动时发现它还在 =
  上次被杀，按存档还原。
- 白名单只撤销"本次临时加的"；用户名单里的应用永久保留。
- 唤醒统计来自 `dumpsys alarm` 的 Top Alarms 段，按增量入账；负增量（计数器重置）丢弃。

**待机耗电怎么排查**（先分清是不是模块自己）：

- **冻结范围是第三方后台**：默认第三方会被冻结 + 掐唤醒锁；`nice=` 的微信/QQ
  不会被冻、也不掐唤醒锁（保活；CPU 由模块本体的熄屏策略决定，熄屏交还时不额外压）；
  `push=` 的微信 push 进程完全放行。
  要随时收消息又不想被压（飞书、Telegram 等）、息屏还要用的（导航、第三方闹钟）
  请加进永久豁免 `white=`；豁免越多，能冻的越少，待机也会更费电。
  反过来，如果更在意待机，可以删掉 `dsleep.conf` 里的 `nice=` 行让 QQ/企业微信
  按普通第三方冻结（微信仍保留 `push=`），代价是这些应用的主进程要等亮屏才恢复。
- **深睡中不再 2 秒巡检**：前 3 分钟冻结窗口结束就改为等 `screen_toggled` 事件，
  亮屏立刻解冻；平时每 5 分钟才醒一次做维护。如果关掉深睡后待机仍明显下降，
  再查冻结进程的 wakelock / 前台服务，而不是巡检。
- **「功能 · 熄屏交还系统」开着时**，熄屏会解除 CPU/GPU 封顶，system 可以满频跑后台
  任务。想压待机可以关掉它（熄屏也封顶），代价是熄屏后台任务变慢。
- 导出的适配包现在带「深度睡眠现场」：`dsleep.conf`、`ds_state`、最近 40 行深睡日志、
  `deviceidle` 的白名单行数和关键状态。待机异常时直接导一份发作者。

需要 root（KernelSU / Magisk / APatch）。冻结优先用系统的 cgroup freezer
（ColorOS 上是 `/dev/freezer`），没有就退到 `cgroup.freeze`，再没有就用 `SIGSTOP`；
7:30 的收口依赖 Android 12+ 的 DeviceIdleController shell 接口。极个别深度定制 ROM
两者都裁掉时，开关能开、状态也会动，但既冻不住也进不了强制空闲——日志里会出现
「已进入」，功耗却不变，遇到这种情况请回报机型。
