# 深度睡眠（V2.2 Beta5）

（返回 [README](../README.md)）

深度睡眠只做一件事：**熄屏后让系统进 Doze 深度空闲，并守住它**。
本版不再冻结任何进程（墓碑冻结已移除），也没有第二套"深睡"状态机。

**新装默认开启；升级用户保留原值。** 打开入口在「睡眠」页顶部的总开关；
关闭时守护不启动，不碰任何系统 Doze 设置。打开后由 `service.sh` 拉起独立守护，
暂停模块会先让它退出并还原。

## 时序（对齐 LSPDoze 的 DeepDoze）

1. 熄屏、没在充电，满 **20 秒**进入深睡流程。
2. 从熄屏算起满 **60 秒**：`cmd deviceidle force-idle deep`；失败补发 `dumpsys` 兼容命令。
3. 收口后按 **1、5、30、60 分钟**复查一次 `dumpsys deviceidle get deep`：
   - 还在 `IDLE`：只排下一次；
   - 掉出来了（来电、闹钟、系统自己退出）：**立刻重新收口**。
     这条"拦截所有退出"恒开，没有开关；走完 60 分钟那一档之后每 60 分钟一次。
4. 亮屏或插电：撤掉临时白名单、`unforce`（只在本次真的 force-idle 过时才发），退出。

维护轮会跟着复查点缩短——不然 5 分钟的维护轮会把 1 分钟那次复查直接睡过去。

闹钟前 30 分钟不收口（Doze 会把闹钟广播压到维护窗口，和"准点响"冲突）；
被挡下时每 60 秒重试一次，闹钟窗口过了下一轮补上。

## 配置

都在 `/data/adb/soc_freqcap/dsleep.conf`：

| 键 | 作用 |
|---|---|
| `enable=1` | 总开关。这是**唯一**的开关：开就做 Doze，关就什么都不做。 |
| `white=包名` | 永久豁免。深睡时也不受 Doze 限制（等同系统「无限制」），对应 LSPDoze 的「网络白名单」。 |
| `nice=包名` | 深睡不碰它（只是保留项，不影响 Doze）。 |
| `push=包名[:进程]` | 把这个包加进 Doze 白名单，保证熄屏后消息还能进来。 |

注意 Doze 白名单是**包级**豁免：`push=` 写的是 `包:进程`，但加进白名单的是整个包。

`doze=` / `appops=` / `freeze=` 这几个旧键写进配置不会报错，但**不生效**——
对应的功能已经移除或合并进总开关了。

## 为什么没有「第二个开关」

以前页面上并排两个都叫 Doze 的开关（自动深度睡眠 / Doze 收口）。冻结移除之后，
关掉 Doze 等于让整个功能空转，留着只会让人不知道该开哪个，所以合成一个。

## 能力边界（重要）

LSPDoze 的 **DeepSleep**（`com.oplus.deepsleep.ControllerCenter`）是 LSPosed 注入
`com.oplus.battery` 进程、hook 私有方法来"进入并赖着不走"的。KernelSU 的 shell 模块
**没有 Java 层 hook 能力**，既读不到那个状态机，也拦不住 ROM 自己的退出。

所以本模块只做 **DeepDoze**（AOSP Doze 加速）这一半，并且是纯 shell 实现：

- 不做「联动省电模式」——会把 `Settings.Global low_power` 置 1，和常亮 AOD 冲突；
- 不做「强制 UID 断网」——那是 OPPO 深睡内部的白名单列表，shell 里无法安全模拟；
- 不做「拦截 ROM 断网」——没有 hook 点；
- 不做「备用进入方案」——同样是 OPPO 私有的第二套进入路径。

要完整复刻 DeepSleep，需要另做一个 LSPosed 模块（hook 目标与报告里列的一致）。

## 其它约束

- **熄屏巡检不拿 system_server 当轮询接口**：亮屏判定先读背光/blank 节点（一次 `cat`），
  节点说灭时最多每 60 秒让 `dumpsys power` 复核一次；媒体 5 分钟、唤醒数 15 分钟才读一次。
- **深睡激活后不再 2 秒轮询**：阻塞等 `logcat -b events -s screen_toggled`，
  亮屏瞬间就醒；平时最长 5 分钟醒一次做维护（复查点临近时自动缩短）。
  logcat 事件不可用时退回 30 秒定时。
- 每个 `dumpsys` 都套 `timeout`，卡住最多丢一轮，不会挂死守护。
- **游戏在前台时不进深睡**：主守护状态里 `game_pkg` 和 `fg` 是同一个包时（典型是熄屏挂机），
  只记一行日志、不收口。Doze 会把游戏挂住，系统也会把这段功耗记进空闲/待机。
- 个别 ROM 的亮度节点在亮屏时也报 0：连续 3 次和 `dumpsys power` 对不上就停用节点，
  改成直接问系统（日志里会写一行）。
- 进入时写 `ds_snap.conf`（本次临时加的白名单）；正常退出删除它。
  启动时发现它还在 = 上次没正常退出，先撤掉里面的白名单再继续。

## 旧版本留下的冻结

升级上来的机器可能有旧账本（`run/freeze.saved`）或残留的 `socfreq_ds` 冻结组。
`service.sh` 每次开机都会**无条件**做一次解冻清理——深睡开关关着也做，
因为"把别人冻住的解开"和"要不要深睡"是两件事。
清理只解冻，不会再冻任何进程。

## 日志

`/data/adb/soc_freqcap/dsleep.log`（超过 256KB 只留最近 128KB）。
能看到每次进入/退出、收口、复查结果（仍在深睡 / 已退出后重收口）。

查看实时状态：

```sh
su -c 'sh /data/adb/modules/soc_freqcap/webroot/api.sh ds_state'
su -c 'dumpsys deviceidle get deep'
```
